# Test Setup Instructions for Dungeon Crawler

This document explains how to set up the test environment for running PHPUnit tests in the Dungeon Crawler Drupal site.

## Prerequisites

Before running tests, ensure you have:

1. PHP 8.3 or higher installed
2. Composer installed
3. A MySQL/MariaDB database server running
4. Access to the required network resources (GitHub, Drupal.org, etc.)

## Initial Setup

### 1. Install Composer Dependencies

From the `sites/dungeoncrawler` directory, run:

```bash
composer install
```

This will:
- Install all required PHP packages including PHPUnit
- Generate the `vendor/autoload.php` file
- Run the drupal-scaffold plugin to create required files like `web/autoload.php`

**Important**: The `web/autoload.php` file is critical for tests to run but is not committed to git (it's in `.gitignore`). It must be generated by composer install/update.

### 2. Configure the Test Database

Tests require a dedicated test database. Update the connection string in `web/modules/custom/dungeoncrawler_tester/phpunit.xml` if needed:

```xml
<env name="SIMPLETEST_DB" value="mysql://your_db_user:your_db_password@127.0.0.1:3306/dungeoncrawler_dev"/>
```

Replace with your actual database credentials.

### 3. Configure the Base URL

If running tests against a local development server, update the base URL in `web/modules/custom/dungeoncrawler_tester/phpunit.xml`:

```xml
<env name="SIMPLETEST_BASE_URL" value="http://localhost:8080"/>
```

### 4. Ensure Temporary Directories Exist

The test framework will create temporary directories automatically, but you can pre-create them with proper permissions:

```bash
mkdir -p /tmp/dungeoncrawler-simpletest/browser_output
chmod 777 /tmp/dungeoncrawler-simpletest
```

### 5. Verify Simpletest Directory Permissions

The `web/sites/simpletest` directory must be writable by the web server user:

```bash
mkdir -p web/sites/simpletest
chmod 775 web/sites/simpletest
```

## Running Tests

### Run All Tests

```bash
./vendor/bin/phpunit --configuration web/modules/custom/dungeoncrawler_tester/phpunit.xml
```

### Run Specific Test Suite

```bash
# Unit tests only
./vendor/bin/phpunit --configuration web/modules/custom/dungeoncrawler_tester/phpunit.xml --testsuite=unit

# Functional tests only
./vendor/bin/phpunit --configuration web/modules/custom/dungeoncrawler_tester/phpunit.xml --testsuite=functional
```

### Run Single Test

```bash
./vendor/bin/phpunit --configuration web/modules/custom/dungeoncrawler_tester/phpunit.xml --filter=testCharacterLoadApiNegativeNoAuth
```

### Run with Code Coverage

```bash
./vendor/bin/phpunit --configuration web/modules/custom/dungeoncrawler_tester/phpunit.xml --coverage-html tests/coverage
```

## Troubleshooting

### "Failed to open autoload.php" Error

This means the `web/autoload.php` file is missing. Run `composer install` to generate it.

### "Failed to open settings.php" Error

This typically indicates:
1. The `web/sites/simpletest` directory doesn't exist or isn't writable
2. The test database connection is misconfigured
3. Insufficient disk space or file permissions

The improved error messages in `FunctionalTestSetupTrait.php` will provide more specific information about the failure.

### Database Connection Errors

Ensure:
1. The database server is running
2. The database specified in SIMPLETEST_DB exists
3. The user has proper permissions (CREATE, DROP, ALTER, etc.)

### Permission Errors

Tests create temporary directories in `web/sites/simpletest/[lockId]`. These directories must be:
1. Created successfully (directory must be writable)
2. Have appropriate permissions for reading/writing settings.php files

## CI/CD Setup

When running tests in a CI/CD pipeline:

1. Install dependencies: `composer install --no-interaction`
2. Ensure database is available and configured
3. Set appropriate environment variables for SIMPLETEST_DB and SIMPLETEST_BASE_URL
4. Ensure /tmp is writable (most CI environments provide this)
5. Clean up simpletest directories between runs to avoid conflicts

Example CI command:
```bash
cd sites/dungeoncrawler
composer install --no-interaction
./vendor/bin/phpunit --configuration web/modules/custom/dungeoncrawler_tester/phpunit.xml
```

## Additional Notes

- The `web/core` directory is tracked in git for this project (unusual for Drupal projects)
- Functional tests will create and destroy temporary Drupal installations in `web/sites/simpletest/`
- Each test run gets a unique lock ID for isolation
- Test data is automatically cleaned up after each test
